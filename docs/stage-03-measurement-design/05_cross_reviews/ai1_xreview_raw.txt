# 2. Changes to my own first-pass design

## Eligibility thresholds

**Old value (Design A §7):**

* Open.
* Required profiling before locking.

**New value:**

* Separate universe membership from trust eligibility.
* Add explicit trust gate.

**Reason:**
Design B improves implementation clarity while preserving the stakeholder requirement that holds remain visible and evidence-limited items do not consume capacity.

---

## Candidate-price algorithm

**Old value (Design A §17A):**

* "Generate candidate prices."

**New value:**

* Candidate prices must come from observed historical item prices only.
* No synthetic prices.
* Remove current price from change candidates but preserve it as baseline.

**Reason:**
The decision is a pilot recommendation based on historical evidence. Invented prices would exceed the evidence contract.

---

## Model family / engine

**Old value (Design A §17A):**

* Regularized regression or tree-based regression.
* Exact family deferred.

**New value:**

* Lock a regularized predictive demand model selection rule before Stage 4.
* Preferred implementation: inspectable log-price regularized regression.

**Reason:**
Mode A requires the predictive contract to be fixed before builders run. An open model family creates uncontrolled analytical degrees of freedom.

---

## Minimum-gain rule

**Old value (Design A §26):**

* Open.

**New value:**

* Remains open pending owner/analyst choice.

**Reason:**
The packet does not establish an evidence-based minimum revenue uplift. Adding one only to reduce recommendation count would introduce an unsupported policy choice.

---

## Segment minimums

**Old value (Design A §13):**

* Open.

**New value:**

**Reason:**
No profiling evidence supplied justifies a segment reporting threshold.

# 4. Items requiring a human (owner) choice between defensible alternatives

## Current price definition

Alternatives:

1. Use week 11617 price because it contains the decision date.
2. Use prior completed week 11616 price because it avoids partial-week ambiguity.

Recommendation:
Use the definition most consistent with Morgan's operational pricing review process. This is a business timing choice, not purely a statistical choice.

---

## Minimum revenue-gain threshold

Alternatives:

1. No minimum gain; rank all trusted positive expected gains.
2. Require a minimum uplift to reduce operational noise.

Recommendation:
Start without a minimum unless operational capacity or review burden requires one. A minimum threshold is a policy choice, not an analytical truth.

---

## Department scope

Alternatives:

1. Keep all five grocery/household departments and let trust eligibility remove thin items.
2. Remove sparse departments before modeling.

Recommendation:
Keep the broader universe and apply item-level trust filtering. This preserves auditability.
